# ============ ГЕНЕРАТОР АРХИТЕКТУРЫ И СКЕЛЕТА ВЫПУСКА (адаптация Скелет.md) ====

Ты создаёшь НЕ сам сценарий, а каркас и правила для будущей генерации частей выпуска по теме «$topic».

## Параметры проекта
— Канал: «$channel_name». Описание: $channel_description
— Формат: атмосферные нарративные истории под засыпание/фон; длинный спокойный монолог одного рассказчика.
— Язык выпуска: $language. Весь текст — на этом языке.
— Текст будет писаться в $number_of_parts частях.
— Суммарный объём: не ниже $min_total_characters знаков.
— Объём одной части: $min_characters–$max_characters знаков. Лучше короче и плотнее, чем длиннее с повторами.
$script_notes
## Переменные и границы частей
— Часть 1 = вступление.
— Если частей $number_of_parts ≥ 3: части со 2-й до предпоследней = основной блок (body); последняя часть = финал.
— Один body-чанк = одна ключевая идея. Финальный чанк не является обычной body-идеей.
— Факты и биографию не выдумывать; спорные детали — только если общеизвестны или обходись без них.

## Критерий отбора идей
— Ровно $body_parts_count ключевых идей для основного блока.
— Не очевидные и второстепенные, а самые сильные, знаковые и небанальные для темы.
— Одна body-часть = одна идея, раскрытая глубоко, без перескока на другую тему.
— Идеи выстраивай по принципу эскалации: $escalation_principle.

## Голос и тональность
— Рассказчик: $narrator_rule.
— Обращение к слушателю: $address_rule.
— Тон: $tone. Речь звучит как живой структурированный монолог без расхлябанности.
— Аудитория: $audience. Термины сразу поясняй: $explanation_style.
— Запрещено называть рассказчика: $forbidden_self_names.

## Логика вступления (часть 1)
— Объём вступления: $intro_length_min–$intro_length_max знаков.
— Начало по формуле: $greeting_formula. Вступление в тему: что это, почему важно.
— Без представления себя и без биографий на старте. Первый абзац — сразу содержание и конфликт.
— Заложи макро-петлю: вопрос/напряжение, которое закроется только в финальной части.
— Не раскрывай главный ответ во вступлении.
— Допустимые типы хуков: Scope Escalation, Counter-Intuitive Reframe, List-of-Questions (Prophetic/Experiential — только при опоре на общеизвестные факты).

## Логика body-чанков
— Каждый чанк открывается напряжением, парадоксом или сильным утверждением; напряжение удерживается до конца.
— На границах чанков: зафиксировать установленное и поднять ставки следующего — без шаблонных фраз и без объявления структуры.
— Внутренняя структура: утверждение-хук → сдвиг определения → ключевой insight → иллюстрация (только в «чанках с примерами») → эскалация следствий → осложнение → частичное разрешение → переход.

## Логика финального чанка
— Не резюмировать списком. Переосмыслить идеи, закрыть макро-петлю, связать финал минимум с тремя предыдущими идеями без пересказа.
— Оставить открытое напряжение или фундаментальный вопрос. Жест к реальной жизни слушателя.
— Последняя строка финала — строго «$final_phrase» и ничего после.
— CTA: $cta_rule.

## Правила примеров
— Чанки с примерами выбери сам (5–7 номеров из основного блока; если частей мало — разумно сузь).
— В остальных частях примеры запрещены. Примеры не превращать в сценизацию и диалог.

## Формы чанков (8 штук, использовать без повтора в соседних частях)
1: утверждение → сдвиг определения → ключевой insight → следствие → неразрешённая граница
2: общее допущение → опровержение → пример/кейс → осложнение → принцип перехода
3: вопрос → напряжение → insight → цена/последствия → частичное разрешение
4: два возможных следствия → напряжение между ними → граница объяснения → цена вопроса → частичное разрешение
5: парадокс → явное называние парадокса → попытка разрешения → почему простое разрешение невозможно → следствие для практики
6: масштаб претензии → сужение к конкретному случаю → разрыв между ними → что это означает системно → открытый вопрос
7: историческое или концептуальное противопоставление → точка пересечения → что остаётся нерешённым → актуальность для настоящего
8: малое наблюдение → расширение до структурного принципа → проверка принципа на пределе → где принцип ломается → принцип перехода

## Запреты
— Не пиши сам сценарий. Никаких ярлыков «Пример:/Вывод:/Итог:».
— Не выдумывай факты, даты, биографию, статистику.
— Запрещённые формулировки для этой темы подбери сам (10–15 шт.) и выведи в forbidden_phrases.

## Формат вывода — строго один JSON-объект, без текста вокруг:
{
  "description": "2–3 предложения о выпуске",
  "anchors": ["якорь 1", "..."],                    // 10–16 пунктов: утверждения, напряжения, парадоксы, следствия
  "chunks_with_examples": [3, 5, 7],                // 5–7 номеров частей основного блока (или меньше, если частей мало)
  "forms": ["форма 1 строкой", "... 8 форм"],       // по одной строке на форму из списка выше
  "ideas": ["идея части 2", "..."],                 // ровно $body_parts_count идей
  "forbidden_phrases": ["штамп 1", "..."],          // 10–15 заезженных формулировок темы
  "self_instructions": ["правило 1", "..."],        // 10–14 правил для генерации частей
  "number_of_parts": $number_of_parts,
  "body_parts_count": $body_parts_count
}

Валидация перед ответом: ideas ровно $body_parts_count; number_of_parts совпадает; примеры внутри основного блока; нет выдуманных фактов; это JSON, а не текст.
